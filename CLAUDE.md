# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is the canonical agent guide. `.github/copilot-instructions.md` is a short pointer to it — update this file first.

## What this is

A personal NixOS configuration for three machines, built with the [Dendritic pattern](https://vic.github.io/dendrix/Dendritic.html) using [`github:denful/den`](https://github.com/denful/den) and [`flake-parts`](https://flake.parts/). All Nix modules under `modules/` are auto-imported via `import-tree`. The checkout also hosts the local [iii](https://iii.dev) agent/worker stack.

**Do not edit `flake.nix` directly** — it is auto-generated by `flake-file`. Edit the `flake-file` declarations under `modules/` instead, then run `nix run .#write-flake` to regenerate it.

## Commands

`just` is the task runner. Run `just` or `just help` to list recipes.

| Command | Alias | What it does |
|---------|-------|-------------|
| `just switch` | `just s` | Rebuild and switch (current host) |
| `just boot` | `just b` | Rebuild and set boot entry |
| `just build` | `just bd` | Build without activating |
| `just test` | `just t` | Test configuration |
| `just fmt` | `just f` | Format all files (`nix fmt`) |
| `just check` | `just c` | `nix flake check` |
| `just update` | — | Update all flake inputs |
| `just generate` | `just g` | Regenerate generated files |
| `just gate` | — | Format and require a clean Git tree |
| `just gate-full` | — | `gate` plus a no-build flake check |
| `just ci` | — | Reproduce CI against committed `HEAD` |
| `just sops-update [FILE]` | `just sou` | Update SOPS keys on secrets |
| `just system-update` | `just su` | generate + update + switch |
| `just generations` | `just ge` | Show NixOS generations |

For remote/specific hosts: `just host::switch HOST`, `just host::boot HOST`, `just host::build HOST`.

Enter the default dev shell with `nix develop`. Alongside nixd, nixfmt, statix, deadnix, jujutsu, nh, just, treefmt, and deploy-rs, it provides nixos-anywhere, omnix, nix-du, nurl, cachix, and the pinned iii binaries. A separate LaTeX shell is available with `nix develop .#latex`.

### Validation and CI

`just ci` requires a clean, committed tree. It archives `HEAD` into a temporary directory, copies `ci/ci-runtime.nix` to `modules/ci-runtime.nix` there, and runs `nix flake check --no-build --accept-flake-config`. The injected `_module.args.CI` disables boot and bootloader configuration and swaps out packages whose builds embed deferred filtered source trees that `--no-build` can never realize: anivim's neovim Ruby provider (dropped), and the flake-built hyprland, walker, and omnix packages (replaced by their nixpkgs builds). Real systems keep the flake packages, and CI still evaluates all three hosts without building their system closures or modifying the checkout.

GitHub Actions runs that same recipe on pushes and pull requests. After a successful push check, the `cachix-push` job builds every exported package and publishes it to the `heraldofsolace` Cachix cache, which is already configured as a flake substituter.

## Architecture

### Module layout

```
modules/
  aspects/        # Feature bundles (Dendritic aspects)
  devshells/      # Default and LaTeX development shells, including pinned iii binaries
  flake/          # flake-parts config (flake inputs, formatter, templates, etc.)
  hosts/          # Per-host configuration
    andromeda/    # ASUS ROG STRIX X570-E desktop (Ryzen 9 5950X, ZFS + impermanence)
    miranda/      # ASUS ROG STRIX B550-A server (ext4; media, Nextcloud, Ollama)
    horologium/   # Lenovo ThinkPad T14 Gen 4 work laptop (LUKS, fingerprint reader)
  users/
    aniket/       # Primary user config (per-host aspects, SOPS keys, SSH keys)
    hass/         # Home Assistant service user
    nginx/        # nginx service user
    nextcloud/    # Nextcloud service user
  defaults.nix    # Global NixOS/homeManager defaults applied to all hosts
  namespace.nix   # Declares the `blazar` namespace
packages/         # Custom packages (auto-exported via pkgs-by-name-for-flake-parts)
templates/        # Typst and Rails flake templates
secrets/          # SOPS-encrypted keys, user passwords, and nixflix credentials
ci/               # CI-only runtime module injected by `just ci`
```

### Dendritic / den concepts

- **Namespace**: `blazar` (declared in `modules/namespace.nix`). All aspects live under `blazar.<name>`.
- **Aspects** (`modules/aspects/`): self-contained feature modules. Defined with `blazar.<name>.nixos`, `blazar.<name>.homeManager`, etc. Reference other aspects in `includes = with blazar; [...]`.
- **Hosts** (`den.hosts.x86_64-linux.<hostname>`): defined in `modules/hosts/<name>/system.nix`. Declare which users they have and which aspects are active.
- **Users** (`den.aspects.<username>`): defined in `modules/users/<name>/user.nix`. The `includes` list in the user aspect drives which feature aspects apply.
- **Defaults** (`den.default.*`): settings in `modules/defaults.nix` and `modules/aspects/defaults.nix` propagate to all hosts/users.
- **`den.schema`**: controls aspect routing, e.g. which classes get pulled into flake-parts outputs.

### How features are composed

The user `aniket` (`modules/users/aniket/user.nix`) includes shared aspects for SOPS, 1Password, OMP, CLI tooling, keyboards, and virtualization, then adds host-specific aspects conditionally:

```nix
++ (lib.optional (host.name == "andromeda") [ ai hyprland desktop games ])
++ (lib.optional (host.name == "miranda") [
  ai
  media._.nixflix
  utils._.monitoring
  utils._.backup
])
++ (lib.optional (host.name == "horologium") [ plasma desktop games ])
```

Machine-level aspects in `modules/hosts/<name>/system.nix` separately compose storage, bootloader, hardware, and host-specific services.

### Host-specific notes

- **andromeda**: ASUS X570-E desktop with a Ryzen 9 5950X and AMD Navi 21 GPU. ZFS root with impermanence (`/persist`); SSH host keys live in `/persist/etc/ssh/`. Includes `stylix`, `impermanence`, `determinate-nix`, and Samba.
- **miranda**: ASUS B550-A server with a Ryzen 7 5800X, ext4 NVMe root, and a separate storage HDD. Runs nginx, Plex/nixflix, Nextcloud, PostgreSQL, monitoring, backups, and Ollama/Open WebUI. A systemd timer renews its Tailscale TLS certificate. Includes `stylix` and `determinate-nix`; it does not use ZFS or impermanence.
- **horologium**: Lenovo ThinkPad T14 Gen 4 work laptop with a LUKS-encrypted root and GRUB. Includes `stylix` and `determinate-nix`; fingerprint support uses the custom `libfprint-goodixtls-55x4` package.

### Disk layouts and recovery

Andromeda and Miranda import disko configurations from their `_disko.nix` files. These describe the live filesystems and swap devices during normal rebuilds without reformatting; use `nixos-anywhere --flake .#<host> root@<target-ip>` only for installation onto blank disks. Horologium defines its LUKS/GRUB setup directly and has no `_disko.nix`.

### Remote access

Miranda is a tagged Tailscale host, so its name does not resolve for SSH — `ssh miranda` fails. Reach it over the LAN with `ssh aniket@192.168.0.4` or `ssh aniket@miranda.lan.internal`. Key auth only (`PasswordAuthentication = false`). The `miranda.dorper-ghost.ts.net` name in `modules/hosts/miranda/system.nix` exists for Tailscale TLS certificate renewal, not for SSH.

### Secrets

Secrets are managed with `sops-nix`. Encrypted files are `secrets/user-passwords.yaml`, `secrets/keys.yaml`, and `secrets/nixflix-keys.yaml`. Update recipients with `just sops-update` (or `just sou secrets/<file>`). `.sops.yaml` authorizes Aniket's key plus all three host keys. The SOPS GPG keys are derived from SSH host keys; `sops.gnupg.sshKeyPaths` checks both `/persist/etc/ssh/ssh_host_rsa_key` and `/etc/ssh/ssh_host_rsa_key`.

### Formatter

`nix fmt` runs treefmt with `nixfmt`, `deadnix`, `statix`, `shellcheck`, `ruff`, `taplo`, and `mdformat`. `toml-sort` is intentionally absent because it conflicted with taplo. Agent profiles and skill documents are excluded so Markdown formatting cannot break their YAML frontmatter. Configuration is in `modules/flake/formatter.nix`.

### Overlays

`modules/defaults.nix` defines a `latestPackages` overlay that imports `inputs.latest` as `pkgs.latest` and pulls selected packages (including `_1password-gui`, `tailscale`, `jetbrains`, `kstars`, `obs-studio`, and `seerr`) into the stable nixpkgs set. NUR and Hyprland-contrib overlays are also applied.

## iii agent stack

The repository root is also an iii compose project:

- `worker-compose.yaml` declares workers; start the stack with `iii compose --up`.
- `config/<id>.yaml` stores persistent worker configuration. Inspect it with `configuration::get` / `configuration::schema` and change live values with `configuration::set`.
- `agents/` contains agent profiles, including `nixos` and `iii-ops`; `skills/` contains worker skills, with repo-local iii skills under `skills/iii/`.
- `data/`, `.iii/`, and `worker-compose.lock` are generated runtime state, not source files to edit.
- `.env` supplies provider credentials to `llm-router`; never print its contents.

The iii binaries are pinned in `modules/devshells/default.nix`; the console listens on `http://127.0.0.1:3113`. The IDE worker currently sets `fs.allow_unjailed: true`, with environment files, keys, secrets, `/etc/passwd`, and `/etc/shadow` protected—run the stack only where whole-host filesystem access is intended.

## Project templates

`modules/flake/templates.nix` exports Typst and Rails templates backed by `devenv`:

```sh
nix flake init -t github:heraldofsolace/nixos-config#typst
nix flake init -t github:heraldofsolace/nixos-config#rails
```

Run these in an empty directory, then use `direnv allow` or `devenv shell`.
