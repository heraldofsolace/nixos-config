# Working on this repository

This is Aniket's personal NixOS flake (`/home/aniket/my-nix`): the Dendritic pattern with
`den` + `flake-parts` + `import-tree`. Everything under `modules/` is auto-imported, so a
feature is a self-contained file. Namespace: `blazar`.

- Aspects: `modules/aspects/<name>/*.nix`, declared as `blazar.<name>.nixos` /
  `blazar.<name>.homeManager`, referencing siblings via `includes = with blazar; [ ... ]`.
- Hosts: `modules/hosts/<host>/` — `andromeda` (ZFS + impermanence), `horologium` (LUKS +
  GRUB), `miranda`. Users: `modules/users/<name>/user.nix` — `aniket`, `hass`, `nextcloud`,
  `nginx`. Adding a feature means adding it to a user's `includes` list, not to a host file.
- `flake.nix` is GENERATED by `flake-file`: never edit it. Edit `modules/flake/*.nix` (or the
  contributing module) and run `nix run .#generate-files`. That same command also regenerates
  `README.md` from `modules/flake/readme.nix`, so README changes go in the Nix module.
- Custom packages live in `packages/<name>/package.nix` (auto-exported by
  `pkgs-by-name-for-flake-parts`) and CI pushes them to the `heraldofsolace` Cachix cache.

## Commands

Run `just` to list recipes: `just build` (bd), `just test` (t), `just switch` (s),
`just fmt` (f), `just check` (c), `just generate` (g), `just update`, `just su`
(generate + update + switch). `nix develop` gives nixd, nixfmt, statix, deadnix, nh, just,
treefmt, deploy-rs, the pinned `iii` engine binaries, and more.

Prefer `just build` / `nix build` and `nix flake check` over `just switch`: activating a live
host is the user's call. Never run `sudo`, `just switch`, `just boot`, or a reformat/reinstall
(disko, `nixos-anywhere`) unless the user explicitly asked for it.

## Conventions

- Format with treefmt (nixfmt, deadnix, statix, mdformat, taplo, shellcheck): run `just fmt`
  before you finish. Keep diffs minimal and match the surrounding file's style; comment why,
  not what.
- Secrets are SOPS-encrypted under `secrets/`. Never decrypt, print, or commit plaintext.
  Files matching `**/.env`, `**/*.pem`, `**/*.key`, `**/secrets/**` are non-accessible by
  policy — do not try to work around that.
- Hosts keep their disko layout in `modules/hosts/<host>/_disko.nix`, in sync with the real
  partition UUIDs; it also drives the live `fileSystems`/`swapDevices`.
- The same repo also hosts the local iii engine (`worker-compose.yaml`, `config/`, `agents/`,
  `skills/`). That side is not part of the NixOS configuration: use the `iii-ops` profile for it.

## Definition of done

Report what you actually verified — a build, `nix flake check`, a formatter run — and say so
plainly when something is unverified or when a change needs a switch the user must run.
